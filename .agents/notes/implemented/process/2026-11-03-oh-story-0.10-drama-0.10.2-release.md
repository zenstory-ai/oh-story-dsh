# Agent Note: Oh Story 0.10.0、Drama Skills 0.10.2 与 DSH 0.2.2-alpha.3 适配

Status: implemented

## Problem

0.1.21 发布后，upstream-update 开了三个 issue：Oh Story 0.10.0（#101）、Drama Skills 0.10.2（#102，含 0.10.1）、DSH `0.2.2-alpha.3`（#100，npm `alpha`）。npm `latest` 与 `next` 仍是 `0.2.1-rc.5`。

Oh Story 0.10.0 改了 244 个文件：卷纲、细纲、题材定位、短篇设定改成大白话，新增 `设定/全书梗概.md`，删掉文风裁决、灵感库召回、正文分两批写、每章契约四问，作者记忆只用确认过的条目。DSH 技能桥里写死了上游的文件名、步骤名和命令，单测也钉着上游的一些原文，任何一处被上游删掉都会让桥指向不存在的东西。实际同步后，`author-memory-maintenance.md` 被并进 `author-memory.md`，长篇细纲的情节点表挪到 `outline-template.md` 并缩成三列，短篇写作删掉了三份去味方法副本。

Drama 0.10.2 新增第 12 个 Skill `short-drama-breakdown`（对标拆解），用 ffmpeg 测量作者提供的标杆剧；0.10.1 让同一张参考图只占一个槽位。

## Decision

- 同步 Oh Story 0.10.0 与 Drama 0.10.2，排除规则不变。
- 逐个核对技能桥、原生 hooks 与 Role 代码里引用的上游文件和术语。作者记忆桥改为指向 `author-memory.md`（整理与迁移旧「本书：」条目都在这份里）。其余引用（`storyctl.py chapter check --fix-punctuation`、导入的 Step 2 / Step 10 / Phase 2 / Phase 4、`outline_view.py --check --strict`、分析批次字段等）在 0.10.0 里仍然成立。上游 `story_hook_core.js` 没有改，DSH 的细纲门禁继续照它的 `OUTLINE_MIN_CHARS` 和 `细纲_第N章*.md` 规则执行。
- 单测跟着上游的新位置改：情节点表读 `outline-template.md` 的三列表头，作者记忆断言 `author-memory.md` 里有 `migrate --workspace` 且旧维护文件不存在，去味方法只要求 `story-deslop`、`story-review` 与写手 Role 的 agent-references 三处有。
- `short-drama-breakdown` 加 DSH 桥：只量作者放进项目或在会话里指定的视频、字幕或转写，不经浏览器或网页工具搜索、下载对标，除非作者要求并确认来源；`breakdown_tool.py` 在 DSH 执行环境里跑，宿主缺 ffmpeg/ffprobe 时直接说明，不凭眼估切点和时长。Drama parity、打包冒烟与单测的 Skill 数改为 12，parity 另外要求 `breakdown_tool.py` 存在。
- 0.10.0 卷纲在标题末尾写 `<!-- L1-01 -->` 编号注释，插件的 Markdown 预览原来会原样显示，这次一并修正，见 [Markdown 预览隐藏 HTML 注释](../bug-fix/2026-11-03-markdown-preview-hides-html-comments.md)。
- 默认宿主、开发宿主仍是 `0.2.1-rc.5`。试用线的打包冒烟 `test:dsh:alpha` 改到 `0.2.2-alpha.3`；兼容范围 `>=0.2.2-alpha.2 <0.2.3-0` 和 Cordis / Schemastery peer 已经覆盖 alpha.3 与它带的 `4.0.6-alpha.2` / `3.18.6-alpha.2`，不用改。延续 [0.2.2 试用线](2026-10-29-dsh-0.2.2-alpha-trial-line.md)的做法。

## Alternatives considered

- 等上游把作者记忆维护内容在 DSH 桥里需要的位置固定下来再同步：桥里那句话少改一次。但旧文件已经删了，不同步就要一直停在 0.9.2；内容只是合并到同 Skill 的另一份文件，改一句桥就跟上了。
- 给 `short-drama-breakdown` 不加桥，靠上游的「只读用户在当前会话提供或授权的材料」：上游文案已经覆盖材料来源。但 DSH 的 Preset 可能带浏览器和网页工具，「授权」在模型眼里容易被理解成可以自己去找，对标视频又涉及版权；ffmpeg 缺失时上游也没说不能估。这两点和 `short-drama-edit` 的桥一致，写明成本很低。
- 试用线停在 alpha.2，不跟 alpha.3：省一轮验证。但 npm `alpha` 已经指向 alpha.3，README 写着「试用 alpha」却测的是旧版，说明会对不上。

## Consequences

收益：作者拿到 Oh Story 0.10.0 的大白话大纲和新的开书梗概、Drama 的对标拆解；桥不再指向已删除的资料；卷纲预览不显示脚本注释。

代价：之前记下却没确认过的作者习惯在 0.10.0 下不再生效，作者要重新说一次（上游决定，插件不做迁移）；`short-drama-breakdown` 只有确定性测试和上游自测，真实模型实测仍走审稿链路，没有跑一次对标拆解；alpha 线每次前进都要重跑一轮临时副本的类型与单测。

- 候选源码 `970389a` 在干净克隆中 `pnpm verify:release` 退出 0，打包 Chrome 在 `0.2.1-rc.5`、`0.2.0-rc.2` 与 `0.2.2-alpha.3` 均 `"ok": true`。
