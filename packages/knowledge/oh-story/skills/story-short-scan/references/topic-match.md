# 短篇扫榜结论：落盘与交接

短篇扫榜的结论写进输出目录的 `短篇扫榜结论.md`：Phase 4 写文件头和「扫榜结论」，Phase 5 写「选题匹配」。`/story-short-write` 定目标情绪时会读它，所以作者不必记住上次聊了什么。

## 短篇扫榜结论.md 模板

```
# 短篇扫榜结论：{平台/方向}
- 扫榜日期：{YYYYMMDD}
- 复扫日期：{YYYYMMDD}     # 短篇风口有效期短，通常扫榜后 2-4 周；过了这天结论只当参考
- 数据来源：{榜单文件名 / 作者提供 / 内置知识}
- 聚合表：扫榜聚合.md     # 同目录；内置知识模式写「无」

## 扫榜结论：{平台名称}
{Phase 4 报告正文}

## 选题匹配

### 方向 1：{一句话方向}
- 目标情绪：{读者读完的感觉，如意难平/爽感释放/反转震撼}
- 题材与设定：{题材包 + 核心设定}
- 开头钩子：{前 3 句建立的冲突、身份差或情绪钩子}
- 传播引擎：{反转 / 强共鸣 / 强话题 / 强余韵}
- 复杂度：低/高 — {低：反转、打脸；高：悬疑、虐恋}
- 可行性：高/中/低 — {同方向样本几篇 + 趋势 + 作者素材能否撑住}
- 篇幅/平台：{建议字数 + 目标平台}
- 验证动作：{开写前怎么低成本验证}

### 方向 2 ...
```

2-3 个方向为宜，按可行性排序（高的在前）。

## 规则

- 可行性上限：聚合表标「少」、样本不到 10 篇或来自作者只给的故事名列表 ⇒ 不许给「高」；内置知识模式一律给「中」。
- 重跑时整节替换，不追加第二份；「扫榜结论」和「选题匹配」都保留在同一个文件里。
- 交付时告诉作者路径：「开写时把小说项目建在扫榜时的文件夹里或和它同级，`/story-short-write` 会自动找到；隔得远就把 `短篇扫榜结论.md` 复制到项目根。」
