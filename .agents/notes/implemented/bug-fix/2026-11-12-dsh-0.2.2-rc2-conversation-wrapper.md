# Agent Note: DSH 0.2.2-rc.2 在对话滚动区外多包一层后，工作台照常挂载

Status: implemented

## Problem

在 DSH `0.2.2-rc.2` 上跑打包冒烟，首次启动就卡住：插件的浏览器模块加载了（页面里有插件的标记节点），但欢迎卡「Oh Story 使用引导」一直不出现。原因在挂载位置的查找。欢迎卡挂到 `[data-conversation-content] > [data-conversation-scroll]`，会话里的工作台挂到 `[data-conversation-content][data-conversation-session=…] > [data-conversation-scroll] > [data-slot='conversation.session']`，两处都假定滚动区是对话主体的直接子节点。rc.2 的对话主体改为先渲染新的 `conversation.hero.frame` 插槽，滚动区放在插槽的 `div[data-slot]` 和一层 `div` 里面，所以两个选择器都找不到目标：欢迎卡不出现，有作品的会话里工作台也挂不上。滚动区以下的结构没变，`[data-conversation-scroll] > [data-slot="conversation.session"]` 仍成立，插件 CSS 依赖的正是这一段。

修好挂载后，冒烟又在「浏览器模块里不得残留 `EventSource` 等旧接口」一步失败。这一步从 DSH 合并下发的预加载脚本里，按模块注册语句切出插件自己那一段。rc.2 打包后，DSH 自己的模块 id 改用模板字符串（`` id:`@deepseek-ai/…` ``），冒烟只认双引号 id，于是找不到插件之后的下一个模块边界，一直切到整个文件末尾，把 DSH 自己用的 `EventSource` 也算了进去。插件自己构建的 `lib/client.js` 里并没有 `EventSource`。

## Decision

- 两处挂载查找把「对话主体 → 滚动区」这一步改为后代选择器：`[data-conversation-content]… [data-conversation-scroll]`；滚动区到 `conversation.session` 插槽仍用子选择器，旧宿主上命中的还是同一个节点。
- 打包冒烟的模块边界正则同时接受双引号和反引号 id（用命名反向引用保证首尾引号一致），仍要求 `window.__ModuleLoader__.load` 前缀。

## Alternatives considered

- 把选择器整段放宽为 `[data-conversation-scroll] > [data-slot='conversation.session']`，不再限定对话主体：最简单。但对话主体上的 `data-conversation-session` 与「不在右侧子代理聊天里」两个条件，正是用来只挑出本会话主栏的；去掉会在侧栏也渲染子代理对话时挂错位置。
- 冒烟改为直接拉取插件单独的 `client.js` 检查，不再从合并脚本里切：不受打包格式影响。但这一步要验证的恰恰是 DSH 实际下发给浏览器的内容，单独拉文件会绕开宿主的合并逻辑。

## Consequences

收益：欢迎卡和会话工作台在 `0.2.0-rc.2` 到 `0.2.2-rc.2` 上都能挂载；冒烟在 rc.2 上不再误报旧接口残留。

代价：后代选择器在对话主体内部更宽松；如果 DSH 将来在同一对话主体里渲染第二个滚动区，`querySelector` 会取第一个。冒烟的模块切片仍依赖 DSH 的注册语句格式，下次格式再变还要更新正则。

## Verification

- 在隔离的 rc.2 实例里用 Playwright 读取 DOM：滚动区的父链是 `div.layer` < `div[data-slot]` < `[data-conversation-content]`；用新正则切 rc.2 的合并脚本，18 个模块注册都能识别，插件段落含 `shell.overlay`、不含 `EventSource`。
- 修复后打包 Chrome 冒烟在 `0.2.2-rc.2` 上返回 `"ok": true`。其余宿主线的结果见本次发布 PR。
