# Agent Note: 兼容线从 DSH 0.1.7 整体移到 0.2.0-rc.1

Status: implemented

## Problem

DeepSeek Harness 于 2026-09-28 发布 `0.2.0-rc.1`（npm `next` 标签；`latest` 仍是 `0.1.7-rc.2`）。插件 0.1.11 的 peer 范围是 `>=0.1.7-rc.2 <0.1.8-0`，DSH 0.1.7 起会在安装与加载时按这个范围检查，所以 0.1.11 在 0.2.0-rc.1 上直接被拒（实测：`dsh: installation rejected: Plugin @oh-story/dsh@0.1.11 is incompatible with dsh 0.2.0-rc.1`）。要在新 DSH 上用，必须发一个声明新兼容线的版本。

## Decision

- `packages/dsh-plugin/package.json` 的 20 个 `@deepseek-ai/dsh-*` peer 范围改为 `>=0.2.0-rc.1 <0.2.1-0`，devDependencies 精确钉 `0.2.0-rc.1`；`pnpm-workspace.yaml` 的 overrides 与 `minimumReleaseAgeExclude` 同步到 `0.2.0-rc.1`（后者与锁文件里的 DSH 包逐一对齐，没有多也没有少）；`scripts/native-dsh-smoke.ts` 与 `scripts/native-dsh-real.ts` 的 `dshVersion` 改为 `0.2.0-rc.1`，它决定 `pnpm test:dsh` 真正安装哪个 DSH。Cordis 相关包的范围上游没有变，保持不动。
- 沿用「只兼容一条补丁线」的上界写法（`<0.2.1-0`），与 0.1.10 起的做法一致。
- 插件源码不改。依据：逐个对比 20 个被引用包在 `0.1.7-rc.2` 与 `0.2.0-rc.1` 的 npm 产物，其中 12 个无变化；有变化的集中在 Chat 呈现（运行状态动画、Web 端「工作过程」默认档改为 `detailed`）、桌面端标题栏避让变量、`ToolCallRecovery` 与 `forkSession` 的 `onCreated`，都不在插件读写的接口上。`pnpm verify` 全绿，`pnpm test:dsh` 在 0.2.0-rc.1 上 5 次中 4 次通过。
- 唯一一次失败在「停止当前 DSH Turn 后保留的排队任务」断言（`native-dsh-smoke.ts`），发生在装完新依赖后的第一次冷启动，之后 4 次都没有复现。断言的报错里加上取消前后的 `production` 请求数，下次再出现能区分「取消先于 Turn 发出模型请求」和「排队任务被执行」两种原因。
- README / README_EN / 包 README / `docs/RELEASING.md` 的安装命令、`docs/VALIDATION.md` 的目标版本一起改到 `0.2.0-rc.1`；`VALIDATION.md` 的真实供应商观察仍是 2026-09-25 在 0.1.7-rc.2 上的那次，本次没有重跑。

## Alternatives considered

- **peer 范围同时覆盖 0.1.7 与 0.2.0（如 `>=0.1.7-rc.2 <0.2.1-0`）** — 最强理由：两条线上的用户都能装同一个插件版本，不用在 README 里讲「哪个插件配哪个 DSH」。不采用：CI 与原生集成测试一次只装一个 DSH，放宽的那条线没有人测；0.1.10 正是因为跨补丁线读到已删除的字段才整页空白（#50），DSH 的版本检查本来就是为了在这种情况下给出明确提示。
- **等 0.2.0 正式版再适配** — 最强理由：rc 可能还有破坏性改动，rc.2 一出又要发版。不采用：本仓库此前一直跟 rc 适配（0.1.5-rc.1、0.1.7-rc.2），按上游 release 升级 DSH 的用户会在插件停在 0.1.7 线时被拒绝安装；这次适配不改代码，再跟一个 rc 的成本只是版本号与一次测试。

## Consequences

- **收益**：DSH 0.2.0-rc.1 用户可以装 0.1.12；插件与 DSH 的版本对应仍由 DSH 自己的检查兜底，装错时是明确提示而不是运行时崩溃。
- **代价**：DSH 0.1.7 用户必须停在插件 0.1.11，之后的插件修复不会回到 0.1.7 线。不带版本号的 `npx @deepseek-ai/dsh` 仍解析到 `0.1.7-rc.2`，安装命令必须写明版本，否则会被拒。上游发 `0.2.0` 正式版或 `0.2.1` 时要再改一次上界。那一次冷启动失败的根因还没有确认。
