# Agent Note: Markdown 预览隐藏 HTML 注释

Status: implemented

## Problem

小说、短剧工作台的 Markdown 预览是插件自己写的安全渲染器：表格、任务列表、引用和代码块渲染成 React 元素，原始 HTML 一律当文本显示，链接只放行 HTTP(S)。这个规则原来没有区分 HTML 注释。

Oh Story 0.10.0 把卷纲剧情段的编号挪进标题末尾的注释（`### 第一段剧情：主角入局 <!-- L1-01 -->`），细纲、卷纲模板开头也有「脚本按名读取的字段」这类说明注释；写作汇报模板的 `<!-- author-report -->` 标记也可能出现在作者文件里。升级后，作者在「小说」视图预览卷纲时，每段剧情标题后面都会挂着一串 `<!-- L1-01 -->`，模板注释也会作为正文段落显示出来。

## Decision

`parseMarkdownBlocks` 解析前先去掉 HTML 注释，行为与常见的 Markdown 渲染一致：同一行的、独占一行的、跨多行的注释都隐藏；围栏代码块和行内代码里的注释原样保留；去掉注释后只剩空白的行按空行处理。其余原始 HTML 仍然当文本显示。源码编辑视图不受影响，作者在编辑时仍能看到并修改这些注释。

## Alternatives considered

- 只隐藏标题末尾的注释：改动范围最小，正好对上 0.10.0 的剧情段编号。但模板开头和汇报标记同样是给脚本、给模型看的注释，作者看到也没有用；只处理标题会留下第二种显示问题。
- 换用第三方 Markdown 库（如 markdown-it 关闭 html）：注释、嵌套列表等行为都更标准。但现在的渲染器是为了「原始 HTML 不生效」专门写的小实现，换库要重新审一遍安全边界、包体积和 DSH 客户端的打包，比这次需要的改动大得多。

## Consequences

收益：卷纲、细纲预览只显示故事内容；注释里的剧情段编号和脚本说明不打扰作者。

代价：作者自己写进注释、想在预览里看到的内容也会被隐藏，需要切到源码视图看；渲染器对注释的处理是自己写的，不是完整的 CommonMark（例如缩进代码块里的注释也会被去掉，因为这个渲染器本来就不支持缩进代码块）。

## Verification

- `markdown-preview.test.tsx` 覆盖标题末尾注释、独占一行与跨行注释、段落中间的注释，以及行内代码和围栏代码里的注释保留。
