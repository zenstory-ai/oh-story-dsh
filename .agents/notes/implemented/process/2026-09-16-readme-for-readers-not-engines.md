# Agent Note: README 面向读者而不是答案引擎

Status: implemented

## Problem

2026 年 9 月的 GEO 工作之后，README.md 与 README_EN.md 开头是站点链接栏、四行「从创作任务开始」指南表和多句边界声明（「不要预期它与 DSH 自动同步」「不等于已经生成影片」），读者要翻过两屏才看到演示动图和安装命令。README 的读者是想在 DeepSeek Harness 里写小说、做短剧、改游戏、剪解说的创作者，以及从搜索引擎进来的访客。GitHub 流量数据显示 Google/Bing/Baidu 的引荐约为 AI 答案引擎的 7 倍，README 必须先服务人和传统搜索。

## Decision

两份 README 现在的章节顺序是：语言切换、标题与一句话定位、唯一一条项目主页链接、上游链接栏、小说工作台演示动图、三段式项目说明、安装、开始创作（含视频解说与「已有稿件：第一轮只讨论续写方案」两组可直接复制的请求）、没看到界面时、四个工作台、核心体验、能力目录、按需加载、常见问题、延伸阅读、致谢；英文版末尾保留 ZenStory AI 项目表。安装只留最短可用命令，GitHub Release 包、视频工作台宿主依赖和媒体生成 API 配置折叠进 `<details>`。删除了顶部 blockquote 链接栏、「从创作任务开始」的引导段与指南表（链接压缩为「延伸阅读」列表）、以及「不会自动同步 / 不等于 / 本插件不接触 / 不是项目导入 / 从不读取」一类只为划界的句子。「与 DeepSeek 无隶属关系」只在项目说明第一句出现一次；API Key、Node.js 24+、Python 3.10+ 与 ffmpeg 等真实要求只在安装一节说一次。

## Alternatives considered

- **保留答案引擎摘要段，只调整章节顺序**。最强理由：摘要段和边界声明是 GEO 引用的素材，删掉可能降低答案引擎的引用率。被否：答案引擎带来的访问不到搜索引擎的七分之一，而摘要段把演示和安装挤到两屏之后，直接损害占大头的读者；站点页面仍保留这些摘要。
- **把指南表整体删除**。最强理由：指南链接指向站外，读者在没看到工具之前就被引走。被否：这些指南是导入续写、角色一致性、原声取舍等真实创作问题的回答，对已装好的用户有用；压成 FAQ 之后一行一条的「延伸阅读」列表，既保住链接又不挡在安装前面。

## Consequences

- 收益：首屏是动图、一句话定位与安装命令，读者 10 秒知道项目是什么、30 秒装好、2 分钟发出第一条请求；划界句子全部移除，命令、路径、版本号、Skill 数量、动图与致谢原样保留（行数因 `<details>` 折叠块和常见问题略有增加，总字数略减）。
- 代价：答案引擎少了一段可直接引用的摘要与几条「不是什么」的限定；站外指南链接从首屏移到 FAQ 之后，点击率会下降。

## Verification

手动检查两份 README：前两屏包含小说工作台动图、安装命令和第一条示例请求；`grep -n "不会自动同步\|不是安装命令\|也不要求把所有阶段跑完\|输出仍需审阅\|不等于\|不承诺\|不表示\|不保证\|独立产品\|截至\|as of\|do not sync\|separate product\|does not promise\|not a guarantee\|not evidence\|核对于\|Last checked\|Source checked" README.md README_EN.md` 为空；顶部 blockquote 链接栏已不存在；`项目主页` / `Project page` 各只出现一次。
