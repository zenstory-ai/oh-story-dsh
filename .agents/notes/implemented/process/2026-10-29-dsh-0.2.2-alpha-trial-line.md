# Agent Note: 接受 DSH 0.2.2 预发布线作为试用线

Status: implemented

## Problem

0.1.19 发布后，npm 上 `@deepseek-ai/dsh` 的 `alpha` 标签指向 `0.2.2-alpha.2`（issue #92），`latest`（`0.2.1-rc.2`）与 `next`（`0.2.1-rc.4`）都没动，四套上游 Skills 也没有新版本。插件声明的 `engines.dsh` 与 DSH peer 范围是 `>=0.2.0-rc.2 <0.2.1-0 || >=0.2.1-alpha.1 <0.2.2-0`，所以 0.2.2 宿主会以版本不兼容拒绝加载插件。只把上界改成 `<0.2.3-0` 也不行：semver 只拿同一 `major.minor.patch` 的边界去匹配预发布版，`0.2.2-alpha.2` 碰不到 `0.2.1-alpha.1` 这个下界。另外 0.2.2 宿主带的是 Cordis `4.0.6-alpha.1`、Schemastery `3.18.6-alpha.1`，也落在原来的 Cordis / Schemastery peer 范围外。

0.2.2-alpha.2 是新的小版本线，与 rc.4 相比，插件 20 个 DSH peer 包里有 17 个的类型声明变了，`@deepseek-ai/dsh` 新增五个 bundle 包，并要求 Node.js 24.9+。逐个读完这些差异不现实，兼容性要靠直接测。

## Decision

`engines.dsh` 与全部 DSH peer 加上独立的比较器集合 `>=0.2.2-alpha.2 <0.2.3-0`，Cordis peer 加 `^4.0.6-alpha.1`，Schemastery peer 加 `^3.18.6-alpha.1`。0.2.2 是试用线：README 写明可以用，默认安装命令仍固定 `0.2.1-rc.4`，开发宿主与 lockfile 也留在 rc.4 和稳定版 Cordis。

这改变了 [0.1.17 的做法](2026-10-19-dsh-rc2-oh-story-090-release.md)。那一版停止单独宣传 alpha 线，理由是 rc 与 alpha 同属 0.2.1 序列、范围本来就覆盖。0.2.2 是新的小版本，不放开范围的话 alpha 用户根本装不上，所以这次把它作为有验证的试用线写进 README。

新增 `pnpm test:dsh:alpha`（在 `0.2.2-alpha.2` 宿主上跑打包 Chrome 冒烟），并加入本地发布门禁 `verify:release`；CI 的 packaged 作业仍只跑默认线和 `0.2.0-rc.2`。

## Alternatives considered

- 开发宿主与 lockfile 直接换成 `0.2.2-alpha.2`：类型检查和单测天天跑在新线上，发现问题最早。但它是 alpha，Cordis 也是 alpha，默认用户装的是 rc.4；开发宿主跟着 alpha 走，会让大多数用户实际用的线失去日常覆盖。新线的类型兼容这次用临时副本验证。
- 只放宽范围，不跑 alpha 的浏览器验证：最快，但违反「宿主线没有打包 Chrome 证据就不宣称支持」的发布规则。
- 把 `test:dsh:alpha` 也放进 CI 的必需作业：之后每个 PR 都会自动守住这条线，但 packaged 作业要多跑一轮；alpha 线变化快，下一个 alpha 出来就要换版本号，放在本地发布门禁里够用。
- 等 0.2.2 出 rc 再适配：省一次发版，但在那之前试用 alpha 的用户都装不上插件。

## Consequences

收益：DSH 0.2.2 alpha 用户可以加载插件；新线的兼容性在发版前有类型、单测、契约和打包浏览器四层证据。

代价：范围放开到整个 0.2.2 预发布线，之后的 0.2.2 alpha / rc 未经验证也会被接受，出了问题要靠 upstream-update issue 提醒再测；`verify:release` 多一轮打包 Chrome；CI 不覆盖 alpha 线，平时的 PR 可能悄悄弄坏它，直到下次发版才发现。

## Verification

- 临时副本把开发依赖与 overrides 换成 `0.2.2-alpha.2`、Cordis `4.0.6-alpha.1`、Schemastery `3.18.6-alpha.1` 及配套 Cordis 插件 alpha：typecheck、198 个单元测试、7 个真实 Cordis 契约测试、DSH boundary 与构建全部通过。
- 候选源码 `585f401` 在干净克隆中 `pnpm verify:release` 退出 0，打包 Chrome 在 `0.2.1-rc.4`、`0.2.0-rc.2` 与 `0.2.2-alpha.2` 均 `"ok": true`。
- 真实 provider 未重跑：Skills、技能桥与默认宿主自 0.1.19 的 rc.4 实测以来没有变化；0.2.2 线只有确定性的打包证据。
